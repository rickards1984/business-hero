1. **High — blocking: billed empty answers disappear from meeting token caps.** [ai_text.py:167](/Users/michaelrickards/dev/bh2-AI1d2/backend/services/ai_text.py:167), [executive_meeting_orchestrator.py:545](/Users/michaelrickards/dev/bh2-AI1d2/backend/services/executive_meeting_orchestrator.py:545). An empty response is recorded financially, but its usage is discarded when moving to another provider or raising `AllProvidersFailed`. Only the successful attempt’s tokens reach the caller. Comparing the actual previous wrapper with this commit, an empty `finish_reason="length"` response reporting 9,000 tokens returns **`(None, 9000)` before, `(None, 0)` now**. Repeated reasoning-only responses therefore evade the 50,000/100,000-token caps. Truncated tool-call attempts lose their reported usage similarly. Accumulate reported usage across attempts and preserve it on failure. The existing empty-answer test discards the returned token count, so remains green despite this regression.

Production receives an avoidable provider rejection, and a transport failure can additionally create estimated charges and trip the provider. Validate resolved production models too. The re-pointed `-pro` tests still set the module variable, so no longer protect the production configuration path.

The hook runs before distinguishing `Rejected`, `Truncated`, or an outage, and a true result discards even attached usage. Normal BM-5 refusals work, but the generic hook trusts callers to classify billing correctly; the meeting hook checks error text rather than status. Restrict unbilled retries to confirmed request refusals and test rejection versus usage-bearing failure explicitly. Part-1 sites do not supply this hook, so this is not a demonstrated regression there.
